## 8. Chẩn đoán git trên máy này (mới phát hiện, quan trọng cho agent sau)

### 8.1 `git status` hỏng — im lặng hoàn toàn

```
$ git status --porcelain          → exit=1, stdout=0 byte, stderr=0 byte
$ git --no-optional-locks status  → exit=1, 0 byte
$ GIT_TRACE2=1 git status         → dừng ngay sau "cmd_name status"
```

- **Không phải do `index.lock`**: đã thử với `GIT_INDEX_FILE` (file tạm,
  lock name khác) → vẫn exit 1.
- **Không phải alias/fsmonitor/LFS**: `git config --list` không có alias,
  `core.fsmonitor` không set, tắt `filter.lfs.required` cũng không hết.
- **Chạy được khi có pathspec**: `git status --porcelain -- <thư mục>`
  → exit 0, trả về danh sách. Nghĩa là lỗi nằm lúc quét **toàn bộ cây**.
- Chưa xác định được thư mục nào gây lỗi. Có vài dấu hiệu bất thường ở
  cây: tồn tại thư mục tên **`python ` (có khoảng trắng cuối)** ở repo
  root, và nhiều file tracked báo `D` (đã biến mất thật khỏi đĩa).
- **Cách sống chung**: dùng `git diff --cached`, `git diff <a> <b>`,
  `git ls-files` thay cho `git status`.

### 8.2 Nguyên nhân gốc của mọi lỗi "Unable to write …" / `WinError 5`

Đo trực tiếp:

| kiểm tra | kết quả |
|---|---|
| `whoami /groups` → integrity level | **MEDIUM IL** (không được UAC) |
| nhóm `BUILTIN\Administrators` | **"Group used for deny only"** |
| ACL `.git/index`, `.git/HEAD`, `.git/config` | `Users` = `Write, ReadAndExecute, Synchronize` — **không có DELETE** |
| rename `index` / `HEAD` / `config` | **Access denied** (cả bằng PowerShell lẫn `cmd /c ren`) |
| copy một file khác trong `.git` rồi rename nó | **thành công** (file mình tạo → `CREATOR OWNER` FullControl) |
| mở `.git/index` với `FileShare.None` | **thành công** → không ai giữ handle, không phải do process |

**Kết luận:** shell chạy ở mức trung bình nên token `Administrators` bị
loại (deny-only) ⇒ không có quyền DELETE trên file do người khác tạo
⇒ **không ai rename được file trong `.git/`**. Đây chính là lý do:

- `git commit` bình thường fail ở `update-ref` (git cũng dùng
  lock + `rename`).
- `git update-index` fail với `fatal: Unable to write new index file`.
- AGENTS §17 ghi "update-ref CAS thất bại trên máy này, WinError 5" —
  **đó không phải bug của git mà là ACL**.

**Cách đã dùng để commit** (việc này AGENTS §14 mô tả, nay đã hiểu vì sao):

1. `GIT_INDEX_FILE=<file tạm>` → `read-tree HEAD` → `update-index` →
   `write-tree` → `commit-tree` (các bước này không cần DELETE trong `.git/`).
2. Ghi ref **tại chỗ** bằng `Path.write_text(".git/refs/heads/master")`
   (Write thì được, rename mới bị chặn), có kiểm CAS tay:
   nếu nội dung ref ≠ parent → abort.

**Cách đã dùng để sync index thật** (để 7 file không bị hiện `D`):

1. Copy `.git/index` → file tạm (giữ nguyên format + checksum).
2. Chạy mọi `update-index` trên file tạm (ở `TEMP` rename được).
3. **Ghi byte của file tạm vào `.git/index` bằng `r+b` + `truncate`**
   (ghi tại chỗ — không cần DELETE). Byte giống hệt → checksum SHA-1 cuối
   vẫn hợp lệ.
4. Dựng tasktodo từ **bản đang nằm trong index của session khác**
   (không lấy worktree) rồi mới + block của mình — nếu lấy worktree thì
   WIP chưa staged của họ sẽ bị tôi nuốt vào commit.
5. Backup byte gốc: `%TEMP%\index_baseline.bin` (phục hồi được ngay).
