## Phase 2 — Deterministic Time Mention Parser

### Schema migration (`scripts/t97_schema_migrate.py`)

Tạo 4 bảng mới (additive, IF NOT EXISTS):
- `time_mentions` — raw span + precision + CE year + extraction_method
- `events` — curated event records (candidate/reviewed/disputed/rejected)
- `event_entities` — event ↔ entity (place/person/text)
- `event_evidence` — event ↔ source span + cbeta_ref

Backup tự động trước khi apply: `data/lineage.db.backup_t97_YYYYMMDD_HHMMSS`
Rollback: `python scripts/t97_schema_migrate.py --revert` (DROP 4 tables)

### Parser (`scripts/t97_parse_time_mentions.py`)

Regex patterns (evidence-first — không tự tạo CE year):

| Pattern | Precision | CE year? |
|---------|-----------|---------|
| `(\d{3,4})年` | year | ✅ từ regex |
| `([^\d]{2,8})(\d{1,3})年` | reign_era | ✅ chỉ khi DILA time_periods match |
| `(唐\|宋\|...)(朝\|代\|...)` | dynasty_period | ✅ từ DYNASTY_RANGES constant |
| `後\|前 + N年` | relative | ❌ không tạo CE year |
| fallback | unknown | ❌ |

Import từ place_timeline_events.year nếu precision=unknown → method=imported.

## Phase 3 — Event Candidate Workflow

### Backend APIs (app.py)

| Route | Method | Mô tả |
|-------|--------|-------|
| `/daoanh/api/events` | GET | List events, filter by status + place_id |
| `/daoanh/api/events/<id>` | PATCH | Update review_status + notes |
| `/daoanh/api/places/<id>/time-mentions` | GET | Time mentions cho 1 địa danh |

PATCH body: `{status: candidate|reviewed|disputed|rejected, notes: str}`

### Admin UI (`admin/events.html`)

- Danh sách event candidates, filter by status + DILA ID
- Pagination 25/page
- Mỗi card: title_zh/vi, năm CE, status chip, evidence (source_record + source_ref)
- Buttons: ✓ Xác nhận / ⚠ Tranh chấp / ✗ Từ chối / ↩ Đặt lại
- Notes input per event
- Toast message khi update
- Link từ admin/index.html
