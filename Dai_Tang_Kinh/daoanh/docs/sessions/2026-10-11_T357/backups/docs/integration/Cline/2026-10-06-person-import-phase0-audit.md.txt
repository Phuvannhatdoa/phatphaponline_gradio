## 4. P0-1 (blocker) — *"Không được sửa `app.py`"* vs. tính năng cần đường ghi

**Mâu thuẫn:** tính năng import phải được gọi từ trình duyệt ⇒ cần **POST route**;
route chỉ tồn tại trong `app.py`; và §2 #12 đã xác nhận **không** route nào tạo người mới.
Ràng buộc "không đụng `app.py`" nếu hiểu cứng sẽ **chặn luôn tính năng**.

| | Phương án (a) — **ADDITIVE route** (khuyến nghị) | Phương án (b) — offline script |
|---|---|---|
| Cách làm | Thêm 1 route POST mới trong `app.py` (chỉ **+**, không sửa route cũ), logic import nằm trong script ngoài `scripts/`, trang `admin/person_import.html` gọi API + hiển thị tiến trình | `scripts/t253_person_import.py` chạy tay trên server; trang HTML chỉ validate/tải file |
| Tiền lệ sẵn có trong repo | **Có** — `POST /daoanh/api/admin/cbeta/import-xml` (`app.py:10167`) load module ngoài bằng `importlib` (`:10193` → `data/cbeta/import_cbeta.py`); frontend `cbeta-import.html` fetch (`:263`) + refresh sau 1,2 s (`:270`) | Có (các script ETL kiểu T203/T251) |
| Trách nhiệm an toàn | Route mỏng + `verify_session` + guard: sau khi thêm, `git diff app.py` **chỉ có dòng `+`** | Không đụng `app.py` = 0 rủi ro regression route |
| Nhược điểm | Vẫn phải đụng `app.py` (nhưng additive, diff kiểm được) | Không có tiến trình import live cho Admin bấm |

**Cần Admin chốt (a) hay (b) trước khi mở Phase 1.** Khuyến nghị **(a)**:
đã có tiền lệ giống hệt, Admin giữ được UI tiến trình như `cbeta-import.html`.
