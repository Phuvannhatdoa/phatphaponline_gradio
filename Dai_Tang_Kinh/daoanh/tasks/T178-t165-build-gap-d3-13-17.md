```sql
CREATE TABLE IF NOT EXISTS translation_prompt_metrics (
  id INTEGER PRIMARY KEY,
  measured_at TEXT NOT NULL DEFAULT (datetime('now')),
  source_type TEXT,
  source_len INTEGER,
  prompt_tokens INTEGER NOT NULL DEFAULT 0,
  completion_tokens INTEGER NOT NULL DEFAULT 0,
  total_tokens INTEGER NOT NULL DEFAULT 0,
  model_id TEXT,
  cache_hit INTEGER NOT NULL DEFAULT 0,   -- 0=MISS (gọi LLM), 1=HIT (không gọi, token=0)

CREATE INDEX IF NOT EXISTS idx_prompt_metrics_time ON translation_prompt_metrics(measured_at DESC);
```

### 9.3 ⚠️ KNOWN ARCHITECTURE GAP — BÁO ADMIN (không tự sửa)

`constitution_hash` là **GLOBAL toàn ruleset** (hash 8 phần: rules ⊕ glossary ⊕ exemplar ⊕
label ⊕ json ⊕ pending ⊕ T166 fp). Lookup dùng nó làm key ⇒ **sửa/thêm BẤT KỲ rule nào**
cũng làm đổi hash ⇒ **mọi dòng cache đều MISS** (over-invalidate), kể cả dòng không dính
rule đó. Hệ quả trực tiếp lên acceptance:

- **§8 mục 2** ("dòng B không chọn R → **vẫn HIT**") ❌ **KHÔNG thỏa** — dòng B cũng MISS.
- **§8 mục 2c** ("thêm rule KHÔNG match source X → X HIT 100%") ❌ **KHÔNG thỏa** — thêm rule cũng đổi global hash.
- §8 mục 2b (sửa rule **static** → tất cả MISS) ✅ **đúng** theo thiết kế hiện tại.

**Nguyên nhân** (chứng minh bằng `17k-bis`): sửa 1 rule terminology ⇒ global hash đổi
`e032ebfb35b109c4` → `1e9b1924b9210660` ⇒ lookup MISS dù dòng đó `selected_rule_codes` không
chứa rule bị sửa.

**Cách sửa (CẦN Admin duyệt — task riêng):** lưu **per-rule fingerprint** (hash `rule_text`
từng rule trong `selected_rule_codes`) ⇒ dòng chỉ MISS khi **rule nó thực sự đã chọn** thay đổi.
Blast radius: 1.762 cache row + 15 read site + 4 luồng dịch + cần backfill (row cũ không có
fingerprint ⇒ vẫn `unverified`). **Không tự ý làm trong T178** — vượt phạm vi 5 gap D3/D8 và
cần Admin chọn giữa (a) per-rule fingerprint đầy đủ (b) giữ global hash, chấp nhận
over-invalidate + tài liệu hoá (c) hybrid.

Test `17k` / `17m-bis` **giữ nguyên** để canh giữ hành vi; khi nào sửa, đổi assertion thành
